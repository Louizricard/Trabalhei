# Como Trabalhar

Para toda tarefa não-trivial, siga este fluxo, nesta ordem, sem pular etapas:

1. **Analisar a tarefa** — entender o pedido e o que ele toca no código existente antes de agir.
2. **Explicar o plano** — descrever em texto o que vai ser feito antes de começar a implementar.
3. **Listar os arquivos que serão criados ou modificados** — nomear cada um explicitamente.
4. **Implementar** — só depois dos três passos acima.
5. **Revisar** — aplicar a checklist de `04-qualidade-e-conclusao.md` no próprio código recém-escrito.
6. **Testar** — rodar o app (ou os testes automatizados relevantes) antes de dizer que terminou.
7. **Entregar um resumo** — o que foi feito, quais arquivos mudaram, e se algum critério de conclusão ficou pendente.

Tarefas realmente pequenas e óbvias (ex.: corrigir um typo, ajustar uma cor) podem pular direto para implementar + resumo. Qualquer coisa que toque em mais de um arquivo ou em lógica de negócio segue o fluxo completo.
